# 最佳实践

为了确保 iStock Shell 的扩展命令具有高质量、高可用性和良好的用户体验，建议遵循以下最佳实践。

## 命名规范

### 1. 命令名称

- **中文拼音首字母**: 对于对应 AkShare 接口的命令，推荐使用接口名称的拼音首字母作为命令名（例如：`个股信息查询` -> `ggxxcx`）。这既符合中文用户习惯，又便于记忆。
- **语义化**: 对于通用功能命令，使用清晰的英文单词（例如：`search`, `history`）。
- **避免冲突**: 在创建新命令前，先检查是否与现有命令冲突。

### 2. 文件结构

遵循 `Domain` (应用域) 的模块化结构：

- `src/worker/domains/[domain]/[command]/`
  - `[command].cmd.ts`: 命令定义与元数据
  - `[command].controller.ts`: 控制器
  - `[command].service.ts`: 业务逻辑
  - `[command].model.ts`: 数据模型

## 开发规范

### 1. 数据模型 (Model)

- **严格类型**: 使用 TypeScript 接口或类定义数据模型，确保类型安全。
- **复用性**: 如果多个命令使用相同的数据结构，应提取公共模型。

### 2. 错误处理

- **优雅降级**: 当数据源不可用时，应返回友好的错误提示，而不是直接抛出异常导致应用崩溃。
- **日志记录**: 在开发环境下，合理使用 `console.log` 或框架提供的日志工具记录关键信息。

### 3. 性能优化

- **缓存机制**: 利用 `IndexedDB` 缓存频繁查询且变动不大的数据，减少网络请求。
- **异步处理**: 所有 I/O 操作（网络请求、数据库读写）必须异步执行 (`async/await`)。

## UI 交互

### 1. 参数设计

- **简洁明了**: 选项参数 (`Options`) 应具有描述性的名称和帮助信息。
- **默认值**: 为常用参数提供合理的默认值。

### 2. 用户反馈

- **加载状态**: 长时间运行的操作应有加载提示（框架通常会自动处理，但需确保 Promise 正确 resolve/reject）。
- **结果展示**: 根据数据特点选择合适的展示组件（表格、文本、图表）。

## 代码风格

- 遵循项目的 `ESLint` 和 `Prettier` 配置。
- 保持代码简洁，单一职责原则（Controller 负责路由，Service 负责业务）。
